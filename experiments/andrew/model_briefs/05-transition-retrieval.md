# Assignment 05 · Learn which past transitions to retrieve

## Goal

Build a small episodic model that predicts a machine's next spin by matching its current lag context to earlier transitions from the same machine. The adaptive model weights a fixed set of singleton and pair experts. A learned similarity function could recognize comparable histories even when some lags differ or are missing. The tuning control is **33.224516/60**. [Current adaptive model](../slot_forecasting/adaptive.py), [data dictionary](../main-participants-60-40/DATA.md).

Conditional and attentive neural processes predict a query from observed input/output pairs and learn to emphasize relevant context points. Here each context point is an earlier lag vector and its observed next-spin outcome, and each machine is a new task with its own support set. Causal temporal convolutions are a useful sequence-only comparison if time permits. [Garnelo et al., Conditional Neural Processes](https://proceedings.mlr.press/v80/garnelo18a.html), [Kim et al., Attentive Neural Processes](https://arxiv.org/abs/1901.05761), [Bai, Kolter and Koltun on temporal convolution](https://arxiv.org/abs/1803.01271).

## Build

1. At endpoint `t`, the query key contains the exact previous eight tick slots as categorical payouts with masks. The support set contains up to 64 most recent observed historical outcomes `y_s` with `s < t`. Each support key uses only lags before its own tick `s`. Its value is `1(y_s > 0)`. Include relative age in ticks. An older observed outcome with missing lag slots can contribute only through known matches. Use `causal.tick_arrays()` and `lagged_spins()` to keep alignment consistent.
2. Start with a deterministic retrieval control. Give each candidate a weight in `[0,1]` using a 24-tick recency decay, a masked mismatch penalty and a penalty for low overlap. For example, use `decay * overlap_fraction * exp(-2 * mismatch_fraction)` on the binary lag flags. A row with no shared observed lags has weight zero. Predict win probability as `(sum(weights*y) + α*b_t) / (sum(weights) + α)`, with `α=4` initially and `b_t` the 12-tick pooled-recent win forecast. Keep the conditional positive mix fixed to the adaptive model for official tuning comparisons. Record match mass and effective support `sum(w)^2/sum(w^2)` separately.
3. If fixed retrieval is competitive on grouped training folds, learn a small similarity function. Give a two-layer MLP of width 16 the per-lag match and mask flags, age, and type/signal. Let its sigmoid output replace the fixed similarity term, and retain the explicit decay and overlap factor. Use binary log loss with fixed support caps and natural frequencies. Hold out entire episodes, train only on released examples, and start with 3–10 epochs, CPU batches and a fixed seed. Fit global scaling and population priors inside each fold. Keep one fixed-retrieval and one learned-retrieval run. For a neural experiment use a pinned CPU-compatible dependency or a simple NumPy/SciPy implementation.
4. If time remains, compare one small self-only causal TCN with the same labels, payout head and fold protocol. Use 16 channels, kernel 3, dilations 1/2/4/8 and a 40-tick window. Feed payout one-hots and masks and end the input at `t-1`. Use last-state pooling. A TCN sees temporal order directly, whereas retrieval sees a set of examples with explicit ages. Report this as a control with a separate budget.

## Verification

- Build a toy context with two opposite historical outcomes. Hand-check fixed-kernel probabilities and that the stronger match has the larger weight. With every key masked, recover the recency win prior exactly. Changing the support-list order should leave predictions unchanged.
- For each synthetic endpoint, assert every support tick is strictly older and each support key uses earlier ticks still. Replace same-tick or future payouts with extreme values and confirm predictions are unchanged. Mask one lag and verify it ceases to contribute to matching without acting like 0×.
- Compare adaptive, fixed retrieval and learned retrieval on identical tuning IDs. Report performance by match mass, recent-history support and condition, along with CPU runtime and memory. If a neural run does not improve on fixed retrieval or the adaptive control, report that directly.
