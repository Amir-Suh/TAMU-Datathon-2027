## Findings that motivate the tests

- **Pair identification is slower with sparse history.** Short history had the highest frozen tuning condition ratio at **0.182**. The most probable pair changed between `cutoff-16` and cutoff on **17 of 96** short-history queries, versus **3 of 288** queries elsewhere. Mean posterior mass on pair hypotheses rose from **0.264** at `cutoff-32` to **0.805** at cutoff in short histories. Median usable observations for the leading pair were 36 at cutoff. [Saved trace diagnostics](runs/bayesian-lag-pairs/tuning-trace-evidence/trace_diagnostics.json).
- **Some pairs recur.** With uniform pair priors and population counts fitted out of episode, `(1,3)`, `(2,5)`, and `(4,7)` ranked first in pair posterior mass on **739 of 768** training cutoffs. This includes 170 of 192 short-history queries. These are model-inferred pairs. Estimate a prior from all 28 pair posteriors in each fit partition, and retain support for each pair. [Saved trace diagnostics](runs/bayesian-lag-pairs/tuning-trace-evidence/trace_diagnostics.json).
- **Win and payout errors both matter.** Across tuning conditions, **80–83%** of posterior mass conditional on a pair sits at `|a|=2`. In diagnostic substitutions, using the simulator win probability with the logistic payout mix reduced `R` from **0.124 to 0.055**. Using the simulator conditional payout mix with the frozen Bayesian win probability reduced it to **0.070**. For short histories those ratios were **0.182**, **0.066**, and **0.116**, respectively. These substitutions use simulator answers and show separate error headroom. [Saved trace diagnostics](runs/bayesian-lag-pairs/tuning-trace-evidence/trace_diagnostics.json).

## Stage A · Learn a prior over pair identity

Keep the existing Bayesian rollout, amplitude grid, family masses, recency offset, and 1/96 hazard fixed. For every fit partition, run the frozen uniform-pair model on the prefixes of machines in that partition and capture the **unconditional joint posterior mass** on each of the 28 pairs at the released cutoff. Read observations strictly before the cutoff. For the prevalence estimate, build the auxiliary population prior from fit-partition histories alone. Use the existing population prior fit for actual forecasting.

For pair `j`, define `qbar[j] = sum_i P(pair=j | prefix_i) / sum_i P(any pair | prefix_i)`. This is a one-pass posterior-mass estimate under the uniform model. Machines with weak pair evidence contribute proportionally less. If the denominator is zero, use uniform. Set the new prior conditional on the pair family to `pi[j] = (1-rho)/28 + rho*qbar[j]`. Compare `rho = {0, 0.50, 0.80}`. Keep the total pair-family prior at 0.25 and keep amplitude signs symmetric within each pair. Estimate a single pooled prior across fit episodes. Keep condition labels out of the model, and retain nonzero prior mass for all pairs.

Select `rho` by minimum episode-weighted cutoff win Brier, the squared error between the forecast and the observed win indicator. Log loss and historical prefix Brier are diagnostics. Compare short-history results, pair posterior mass and entropy, and agreement between the leading pair at `t-16` and `t`. A prior can make the posterior settle earlier while settling on the wrong pair, so judge the change primarily by predictive error. Include a synthetic rare-pair case to verify the prior can be overcome. [Bayesian lag selection and interactions](https://arxiv.org/abs/1506.06268).

## Stage B · Tune effect size and reset rate separately

Use the selected Stage A prior, or uniform if it wins. Run each change against that same control.

1. **Effect size.** Add `±3` to the **switching** pair grid. Put probability 0.225 on each of `±1,±2` and 0.05 on each of `±3` both at initialization and on reset. Store the explicit amplitude values and masses in the configuration. The existing `wide=True` configuration also includes `±4` and uses different weights. Keep the singleton grid, hazard, and recency offset fixed. The earlier widened-grid experiment used discounted static evidence, so this test isolates wider effects under switching. Report calibration by win-probability bin, error at high posterior confidence, and performance after synthetic sign reversals.
2. **Reset rate.** Keep the original `±1,±2` grid and compare `1/64, 1/96, 1/144` per tick. A reset redraws the amplitude from its prior and can retain the same sign. Record prequential log loss and Brier on reversal sequences and training cutoff scores by condition. Pair identity stays fixed within each hypothesis.
3. **One combined test.** Try the wider grid with the winning nonbaseline hazard only if each independently improves inner-fold cutoff win Brier by more than `1e-6`. Choose Stage B's minimum episode-weighted cutoff win Brier among the control, single changes, and any eligible combined candidate. The evidence of recurring pair identities makes changing the pair itself a lower-priority follow-up. [Forward filtering and expert switching](https://arxiv.org/abs/0802.2015).

## Stage C · Improve the positive payout distribution with win fixed

Keep the Stage B win forecast fixed and compare three payout heads. In each training fold, refit the saved logistic architecture on the fit partition with its existing settings `C=0.02`, self features only, and 15% prior blend. Use the saved full-train [logistic checkpoint](models/logistic_regression/two_stage_self.joblib) for the tuning run and verify its conditional probabilities against the [frozen logistic CSV](runs/model-comparison/two_stage_self.csv). Use its conditional distribution `r0(t)` with a smoothing weight of 20. The logistic features already include history, so this is a predictive smoothing rule.

| Head | Historical contribution |
| --- | --- |
| Frozen logistic control | No additional observations |
| Recent positive payouts | All observed positive payouts before `t`, with a 24-tick half-life |
| Matching positive payouts | Same recency weights, restricted to observations whose lag-pair parity agrees with the current parity for the leading pair |

Use the leading pair from the posterior at endpoint `t`. Its lag state at an earlier outcome tick `s` uses spins strictly before `s`. Require both pair lags to be observed for each matched outcome and the query. Count only observed positive outcomes with age `t-1-s`. If no matches exist or the current context is unavailable, use the logistic prior. For payout class `k`, compute `r_k = (20*r0_k + weighted_count_k)/(20 + total_weight)`. This keeps rare payouts supported and shrinks sparse contexts toward the trained prior.

Select using episode-weighted five-class Brier on all realized cutoff outcomes, with win forecasts identical across the three heads. Report conditional log loss on the positive rows as a diagnostic, plus positive payout calibration and error by class. Compare matching against the recent-positive control. Also report a diagnostic that rescales the recent-positive counts to the matched head's total local weight. This checks whether any gain comes from matching context or simply shrinking more strongly toward the logistic head. [Five-class scorer](slot_forecasting/contest.py).
