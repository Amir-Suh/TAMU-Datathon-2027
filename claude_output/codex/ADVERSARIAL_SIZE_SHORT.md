## The task and score
Each query is one slot machine at a cutoff tick (8 machines per episode). Predict `[p_0, p_1, p_2, p_5, p_20]` = probabilities of the next payout (0x, 1x, 2x, 5x, 20x). Score = squared error against the simulator's TRUE probabilities, per-condition ratio to a frozen pooled baseline, `points = 60/(1+R)` (baseline 30). Conditions: stable, short_history (each machine shows only 64 observed ticks: the last 40 consecutive plus 24 sampled older), drift, shared_change (a hidden rule flips direction around tick 140-150). Inference must be offline numpy/scipy, 2 CPU cores, 30 minutes; fit-time can use torch/GPU. No test labels exist locally. Using histories (ticks < cutoff) of train, validation and test as self-supervised data is allowed; validation TRUE probabilities may only be used in a final fit.

## What we know (measured in this repo; paths are starting points)
- Win rule (found by a teammate's analysis, `models/FINDINGS.md` on branch `origin/amir_workspace`, vendored at `src/tdx/arms/m3flip/amir/`): each machine's win depends on whether its win/loss at two earlier lags matched or differed, with lag pair (1,3), (2,5) or (4,7) and a direction (match->win or differ->win); in drift/shared_change the direction flips once. Our GRU's sensitivity to lags matches those pairs exactly (a perturbation test).
- Current best validation (dev mode, labels unused) is ~56.6: `src/tdx/arms/seqens` (12 GRUs, `src/tdx/arms/seq/arm.py`) blended by a split-duty rule with the Bayesian `m3flip` (`P(win)` 70% m3 + 30% GRU, size mix from the GRU only; `src/tdx/package/blend.py`, kind "factored"). Single GRU seeds score 52.8-54.5; a 12-seed average 55.8; `m3` alone 55.3.
- Remaining error (oracle test on validation, blend error 0.0131): replacing P(win) by the truth removes 44%, replacing the size mix removes 55%. Machines with a confident lag pair are 80% of machines and 81% of the error, and there a perfect P(win) would remove only 38%: payout SIZE dominates the residual.
- Size facts: type x signal prior size-mix error 0.0316; best hand estimator (recency-weighted counts of past win sizes) 0.0304; GRU (factored win/size head) 0.0165 at the cutoff (out of sample); held-out-tail size log-loss GRU 1.010, m3 1.023, GBDT 1.031, pooled 1.038. A GBDT on win rows with hand features (own previous sizes, EMA rates, gaps, pair features, neighbours) gained only ~1% log-loss over machine type. Size shares are NOT correlated across machines of an episode (permutation tests). Signal (-1/0/1, only at the cutoff) barely moves size. Probing the GRU: its hidden state encodes ticks-since-last-win (R2 0.90), the latest win size (72% acc), running 1x share (R2 0.72) and 20x share (R2 0.41); ~6 of 128 units carry half the size effect. Details: `claude_output/agy/size_probe.md` job output summarised in this brief only.
- Short_history facts: the GRU's short_history loss ratio is ~0.17 (worse than m3's 0.107); the Bayesian m3 is the best there. Masking-based augmentation (`src/tdx/arms/seq2`), a short flag, distillation, token dropout: none gave a reliable gain (backtest improves 2.4% for light masking but validation ties). More GRU seeds do not help beyond ~10 (plateau 55.8). A causal transformer needed a conv front-end + ALiBi to work at all (`src/tdx/arms/tfm2`), then ties the GRU on win and is worse on size.
- Tools you may rely on in your proposals: leak-free tail backtest `python -m tdx.backtest --arm A --variant V --hold 30 [--short]` (refit with the last 30 ticks hidden, scores realized outcomes), decomposed into win part and size part; `python -m tdx.run --arm A --variant V --mode dev` (validation points + per-condition ratios).
